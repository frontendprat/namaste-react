## npm

- It is the default package manager for Node.js.
- Used to install, update, and manage packages.

## Bundlers

Examples:

- Parcel
- Vite

### What is a Bundler?

A bundler takes your application's code and assets and bundles them together into optimized files that can be served to the browser.

Responsibilities:

- Bundling
- Transpiling

- Asset management

## Dependencies vs Dev Dependencies

### Dependencies

Packages required in production.

Example:

```bash
npm install react
```

### Dev Dependencies

Packages needed only during development.

Example:

```bash
npm install -D parcel
```

## Package Version Symbols

### Caret (^)

Allows minor and patch updates.

Example:

```json
"react": "^18.2.0"
```

✅ 18.2.1  
✅ 18.5.0  
❌ 19.0.0

### Tilde (~)

Allows only patch updates.

Example:

```json
"react": "~18.2.0"
```

✅ 18.2.1  
✅ 18.2.9  
❌ 18.3.0

### Asterisk (\*)

Allows any version.

## package.json vs package-lock.json

### package.json

- Stores project metadata.
- Stores dependency ranges.
- Contains scripts.

### package-lock.json

- Stores exact dependency versions.
- Ensures consistency across machines.
- Automatically generated by npm.

## node_modules

- Contains all installed packages.
- Stores transitive dependencies (dependencies of dependencies).
- Generated automatically using `npm install`.

### Rule

> Whatever can be regenerated should not be pushed to Git.

Examples:

- `node_modules`
- Build folders (`dist`)

## React.createElement()

React does **not create HTML directly**.

It creates a React Element (a JavaScript object).

Example:

```js
const heading = React.createElement("h1", {}, "Hello World");
```

React later converts it into actual DOM elements.

## JSX

### Important Points

- JSX is NOT React.
- React can work without JSX.
- JSX is NOT HTML.
- JSX is HTML-like syntax inside JavaScript.

Example:

```jsx
const element = <h1>Hello World</h1>;
```

## JSX Compilation

Babel converts:

```jsx
<h1>Hello</h1>
```

into:

```js
React.createElement("h1", {}, "Hello");
```

## Code for Humans

> First humans, then machines.

Write readable code.

If we wrote code only for machines, we'd write binary.

## JSX Attributes

Use camelCase:

```jsx
className;
htmlFor;
onClick;
```

Not:

```jsx

for

```

## Multi-line JSX

Wrap in parentheses:

```jsx
const heading = (
  <div>
    <h1>Hello</h1>
  </div>
);
```

## JavaScript Inside JSX

Use curly braces:

```jsx

```

## Props

- Props = Properties
- Inputs to Components
- Similar to function arguments

Example:


## Config Driven UI

UI is driven by data/config rather than hardcoded values.

Example:

```js
const restaurants = [...];
```

Then render UI based on that data.

## Keys in `.map()`

Whenever using `.map()`, provide a unique key.

Example:

```jsx
restaurants.map((restaurant) => <Card key={restaurant.id} />);
```

### Why?

- Helps React identify items.
- Improves reconciliation performance.
- Reduces unnecessary DOM updates.

### Avoid

```jsx
key = { index };
```

unless there is no better unique identifier.

## Why Use Libraries/Frameworks?

- Better Developer Experience
- Less Boilerplate
- More Productivity

## useState()

- Creates state variables.
- State changes trigger re-renders.

```js

```

## Virtual DOM

- JavaScript representation of the Real DOM.
- Lightweight object structure.

## React Fiber

React's reconciliation engine.

Responsible for:

- Scheduling updates
- Rendering efficiently
- Prioritizing work

## Diffing Algorithm

Compares:

- Old Virtual DOM
- New Virtual DOM

Finds minimum DOM changes needed.

## React Rendering Flow

```text
State Change
      ↓
Component Re-renders
      ↓
New Virtual DOM
      ↓
Diffing
      ↓
DOM Updates
```

## useEffect()

### Runs on Every Render

```js
useEffect(() => {});
```

### Runs Once

```js
useEffect(() => {}, []);
```

## Rules of Hooks

Always:

- At the top level
- Inside React components

Never:

- Inside loops
- Inside conditions

# Lecture 8

## Class Components Lifecycle

```text
Constructor
      ↓
Render
      ↓
componentDidMount
```

## Why `super(props)`?

Used to initialize React.Component.

Without `super()`:

```js
this;
```

cannot be accessed.

## State in Class Components

### Defining State

```js
this.state = {
  count: 0,
};
```

### Updating State

```js
this.setState({
  count: 1,
});
```

## Functional Component State

```js
const [count, setCount] = useState(0);
```

## Rule

Never update state directly.

## Parent Child Lifecycle

```text
Parent Constructor
Parent Render
Child Constructor
Child Render
Child componentDidMount
Parent componentDidMount
```

## Why is React Fast?

### Render Phase

- Constructor
- Render

### Commit Phase

- DOM Updates
- componentDidMount

React separates both phases for better performance.

## Single Responsibility Principle

A component should have:

- One responsibility
- One reason to change

Benefits:

- Easier maintenance
- Easier testing
- Better readability

## Modularity

Break applications into smaller reusable pieces.

Benefits:

- Reusability
- Maintainability
- Testability
